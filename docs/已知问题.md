# ZCode 飞牛 fnOS 版 · 已知问题

> 适用：3.14.x 全部打包版本 · 均为**上游 / 云端**行为，**不是本 fpk 打包问题**，本仓库不做补丁  
> 记录时间：2026-09-28

---

## 问题一：套餐查询「获取失败」（接口 3001 / parameter error）

### 现象

- 模型设置里 **Start Plan / 体验套餐** 显示「获取失败 / 查询失败」，或「登录后查看」
- 日志（可累计上百次）：

```text
[coding-plan-availability] billing/balance 请求失败 {
  error: 'parameter error',
  providerId: 'account:bigmodel-start-plan',
  status: 400,
  url: 'https://zcode.z.ai/api/v1/zcode-plan/billing/balance?app_version=…'
}
[rpc:call] usage-stats.getEntitlementSnapshot FAIL … ApiError: parameter error
```

### 原因

**账号无 Start Plan 权益**时，上游把「无此权益」误做成笼统 **400 `code:3001 parameter error`**。

| 核查项 | 结果 |
|---|---|
| 登录凭据 | 正常（credentials 可解密，oauth 会话 OK） |
| 网络 / 其它接口 | 同期 `getEnterprisePricing` 等 OK |
| 请求形态 | 极简 GET + Authorization + `app_version` |
| 改参数 / 换 method | 仍 400 或 404/401，服务端对无权益账号行为不友好 |
| JWT | 仅含账号身份，**无 plan 绑定**；账号多为 `bigmodel-individual-coding-plan`，无 start-plan |

### 建议（上游）

- 无 Start Plan 时返回 `code:0` + 空 plans，或专用「未开通」错误码，**勿复用 3001**
- 客户端将 3001 映射为 `coding_plan_not_entitled`，避免无限重试

### 本包处理

- **不**改打包产物（摘 provider 会误伤真有体验套餐的用户；patch 压缩产物成本高）
- **可忽略**该卡片；编码套餐额度走 bigmodel 另一链路，与此无关

### 复现（只读，不打印令牌）

```bash
# 替换 dataDir=应用数据目录、user=应用运行用户后执行
/var/apps/nodejs_v22/target/bin/node - <<'EOF'
const crypto=require('crypto'), fs=require('fs');
const file=`${dataDir}/data/.zcode/v2/credentials.json`;
const data=JSON.parse(fs.readFileSync(file,'utf8'));
const secret=`zcode-credential-fallback:linux:${dataDir}:${user}`;
const key=()=>crypto.createHash('sha256').update(secret).digest();
function dec(v){
  if(!v) return null;
  if(!v.startsWith('enc:v1:')) return v;
  const [iv,tag,ct]=v.slice(7).split('.').map(p=>Buffer.from(p,'base64url'));
  const d=crypto.createDecipheriv('aes-256-gcm', key(), iv); d.setAuthTag(tag);
  return Buffer.concat([d.update(ct), d.final()]).toString('utf8');
}
(async()=>{
  const r=await fetch('https://zcode.z.ai/api/v1/zcode-plan/billing/balance?app_version=3.14.3',
    { headers:{ Authorization:`Bearer ${dec(data['zcodejwttoken'])}` } });
  console.log(r.status, await r.text());
})();
EOF
```

## 问题二：Start Plan 免费套餐「请求被网关安全校验拒绝」

### 现象

- 使用 **官方 GLM / Start Plan 免费套餐** 时报错：  
  **「请求被网关安全校验拒绝，请稍后重试或联系支持」**
- 同界面换成本地 / 自建模型通道则正常

### 原因

不是 API Key 或模型名错误，而是**官方通道被 ZCode 网关 + 边缘风控拦下**：

1. `provider = account:bigmodel-start-plan`（官方 GLM）**不直连智谱**，走  
   `https://zcode.z.ai/api/v1/zcode-plan/anthropic`
2. 网关前有 **阿里云 ESA**（`server: ESA`、`eagleid`、`via: ens-cache…`）做机器人/风控
3. 响应为 **`captcha verify failed`（code 3007）**，并下发验证码 Cookie  
   ZCode 客户端把它归成 `reason=auth_failed` 再包装成上述文案 → **与登录鉴权无关**
4. NAS / 容器 / 机房 **出口 IP** 易被判定为高风险，强制人机验证  
   **headless 服务端无法过验证码** → 必然失败

对比（示例）：

| 通道 | 成功 | 失败 |
|---|---|---|
| 自建 / 局域网模型 | 正常 | 偶发 |
| `account:bigmodel-start-plan`（官方 GLM） | **0** | 全部 captcha verify failed |

### 本包处理

- **无法**在 fpk 内修复：依赖云端风控与是否可完成人机验证
- **规避**：
  - 自建 / 局域网模型通道（不走该网关）
  - 避免在数据中心 / 高频并发下狂刷官方 GLM
  - 如必须用官方通道，在**住宅网络、可控浏览器**环境完成人机验证后再试（不保证 NAS headless 一定成功）

## 两问题关系

| | 问题一 | 问题二 |
|---|---|---|
| 表现 | 套餐卡片「获取失败」 | 官方 GLM 对话/请求被拒 |
| 接口 | `billing/balance` | `zcode-plan/anthropic`（推理） |
| 根因 | 无 Start Plan 权益 + 3001 语义不清 | ESA 人机验证 / captcha 3007 |
| 是否本包 bug | 否 | 否 |

两者都指向 **Start Plan / 官方 GLM 在部分账号与网络环境下不可用**；用自有模型通道时通常不受影响。
